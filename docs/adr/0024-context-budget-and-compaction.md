# ADR 0024 — Context budget, compaction and stored long texts

- **Status:** Accepted (2026-11-26)
- **Spec:** §1.3.1 `count_tokens`, §1.3.5 (budget before every call), §5 (all), §6.1, §14 "Lost context"
- **Builds on:** ADR 0002 (adapters, replay), 0003 #7 (budget check), 0004 (loop), 0007 (append-only
  prompt), 0010 (never switch provider mid-turn), 0015

## Context

Long chats grew without bound: every call resent the whole history, cost and latency grew with it,
and past the window a provider would refuse the request. Spec §5.2 asks for counting before every
call, compaction that keeps decisions, facts, open tasks and corrections, recent turns verbatim,
large tool outputs kept out of the prompt, and a budget split that is configuration.

## Decisions

| # | Decision | Why (evidence) |
|---|---|---|
| 1 | **Counting, cheapest first** (`enzo.brain.tokens`). A local estimate before every call; the provider's usage report of each reply scales the next estimate of that brain up (never below the plain estimate); the provider's exact count only when the estimate passes 80% of a limit. | Neither SDK ships a local tokenizer (checked: `anthropic` 2.9, `openai` 3.53). Both counting endpoints are network calls: Anthropic's is free but rate limited (token-counting docs, read 2026-11-25); OpenAI's `responses/input_tokens` publishes no price. An estimate of 1M characters takes well under 0.1 s (test). Each exact count is logged (`context.count`, with ms). |
| 2 | **The estimate over-counts.** ASCII at a per-provider ratio below the published average (Anthropic 2.0 vs ~2.5 chars/token: "1M tokens ≈ 2.5M Unicode characters", models overview read 2026-11-25; OpenAI 3.0 vs the usual 4; others 2.0), every non-ASCII character as one token, replay data counted as sent. | Being wrong low risks an oversized prompt; wrong high only compacts a bit early. |
| 3 | **Capabilities say what is exact.** Claude and OpenAI API keys: `exact`. A ChatGPT plan sign-in and the OpenAI-compatible xAI/Moonshot routes: `estimate` (local, no request). | The plan route has no counting endpoint (ADR 0013); xAI's and Moonshot's are unverified (§1.3.2, §16: never claim it). |
| 4 | **Budget per brain from configuration** (`[context]` in `brains.toml`, `enzo.compaction.Budget`). Each brain has a sourced `context_window` / `max_output_tokens` (Claude 1M/128K, GPT-6.2 1.05M/128K, read 2026-11-25); unconfirmed ones (Grok, Kimi) get `default_window` 128K. Hard limit = window × 0.9 − reply (16K). At a turn's start the prompt must also stay under min(150K, the brain's long-context price step, limit × 0.75). With a fallback the tighter budget of the two applies. | §5.2 "recorded, not guessed per call". 150K is Anthropic's own server-side compaction trigger (read 2026-11-25); GPT-6.2 doubles input prices past 272K and Haiku 5.5's rise past 100K, so compaction comes first. 25% of the limit stays free for the new task and its tool results. Sonnet 5.5: limit 884,000, compact at 150,000, keep 30,000 (test). |
| 5 | **Enforced before every brain call** in the loop, mid-turn tool steps too (`ContextWindow.fit`). At a turn's start the soft trigger compacts; mid-turn only the hard limit does. Over the hard limit with nothing left to summarize, or the summary failed: the turn stops `over_budget` with an honest message and **nothing is sent**. Over only the soft trigger and the summary failed: the reply uses the whole chat (it fits), the failure is logged and the chat says so. | §1.3.5 "compact first, not send an oversized prompt and hope". Soft triggers only at a turn's start so a turn resets the provider cache at most once. |
| 6 | **Compaction**: older whole turns are summarized; the newest whole turns up to `keep_recent` (30K tokens, at most a third of the trigger) and the current turn stay verbatim. Turns never split, so every tool call keeps its result (#39). | §5.2. |
| 7 | **The summary is a structured record** (`Summary`: story, decisions, facts, open tasks with ids; corrections; stored-text pointers), one row per compaction in `compactions` (migration 0010), saved atomically with its turn. The transcript is never changed. The model writes notes for the newly folded turns only (a `record_summary` tool call, validated); earlier notes are carried by code and leave only when the model retires them by id. | Re-summarizing a summary drifts; an append-only record cannot silently drop a decision. |
| 8 | **Invariants in code** (`summary.check`): every earlier correction stays; each correction is the user's own words, copied by code from the transcript (the model only points at turn numbers); a short message that reads like a correction ("actually…", "no, …", "from now on…") is kept even if the model missed it; every stored-text pointer stays; earlier notes stay unless retired. A violation fails the compaction (decision 5) rather than lose something. | §14 "Lost context: summary invariants". Tests fail when a correction is dropped, reworded or missed. |
| 9 | **The conversation's own provider writes the summary**: its `summary_tier` brain (fast by default), else the conversation's brain; no fallback to another provider. The call is on the ledger as task `compact` and counts in the turn's cost. A long fold is summarized in chunks that fit the writer's window and stay under its long-context price step. | ADR 0010: never switch providers mid-turn. Folding ~120K tokens costs ~$0.012 on Haiku 5.5 (two calls under its 100K step, $0.10/M) instead of ~$0.48 on Opus 5.5. |
| 10 | **The prompt is a pure function** of the stored transcript and the latest record (`build_view`): instructions, the summary as a user-role message (notes, not instructions: it holds words from pages and the user), then the kept turns. Kept messages made before the summary lose their provider replay data (Claude thinking, OpenAI reasoning items); words and tool calls stay. Messages made after it keep theirs. | Claude's preserved thinking binds each block to its prefix: replaying kept turns' thinking after a client-side summary fails the prefix check (Anthropic: "keep-tail compaction … strip the thinking blocks from the retained turns", read 2026-11-25). The view is byte-identical on every later call, so thinking made after the summary stays valid. |
| 11 | **Caching**: a compaction resets the provider cache once (new prefix); from then on the prompt is append-only again (tested across a gateway restart), so caches stay warm until the next compaction. Compaction costs one summary call plus one cache write; each later call sends ~120K fewer tokens. | ADR 0007 kept the history append-only; this keeps it so between compactions. |
| 12 | **Selective retention** (`enzo.tools.stored`): a tool result over `tool_inline_chars` (20,000) is saved whole in Enzo's private data folder (`~/.local/share/enzo/context/<chat>/`, 0700/0600) and the prompt gets its first 4,000 characters (still fenced as outside data) and a pointer. A pasted message over `paste_inline_chars` (100,000) keeps its first and last 4,000 characters (the question usually follows the document). Long parts of folded turns are stored the same way and listed in the summary. `read_stored_output` reads on by offset or `find`; its own results are never shortened. `read_page` / `read_file` may now return up to 1M characters, and messages up to 1M are accepted (was 100K). | §5.2 "replaced with a short excerpt or a pointer", §5.3 "answers from the stored file, not from a truncated prompt". Ids are content hashes: storing is idempotent and a shortened message is the same bytes every time (decision 10). |
| 13 | **No automatic memory writes from compaction.** Durable facts reach long-term memory through `remember` when the user says them (ADR 0020), with their words and turn as evidence. The summary keeps the chat's working facts. | §6.5: record only what evidence supports, keep a source reference. A summarizer reading old turns is second-hand: no exact source, and it could revive a superseded fact. |
| 14 | **The chat says so**: a `compacted` event ("Older messages were summarized to keep this chat fast. Nothing is deleted: the whole chat stays here.", or that summarizing failed), and reopened chats mark the first message after each summary (`summarized` on `/messages`). | §10.3 plain words; the user sees every message, always. |

## Consequences

- Long chats stay below 150K tokens of prompt on every brain (100K on Haiku), and a decision or a
  correction from turn 2 is still in the prompt after 50+ turns (tests read the requests the brain
  received).
- **Not verified live:** real Claude/GPT summaries (no keys in cloud sessions). The laptop script in
  the PR checks it. Anthropic's server-side on-demand compaction could keep kept turns' thinking
  valid; it is Claude-only, so it is left for later.
- The correction backstop is English-only. Summaries grow with each compaction (notes are only
  retired, not rewritten); a summary of the summary would be needed after very many compactions.
- A chat moved to the trash keeps its stored texts (it can still be opened).
